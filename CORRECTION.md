# Data Correction Notice — v1.0 withdrawn, superseded by v1.1

**Date:** 12 October 2026
**Affects:** the dataset archive `datasets.tar.gz` published under release tag `v1.0`
(25 March 2026) and the dataset descriptions in earlier revisions of `README.md`.

## Summary

A self-audit of the released data found **label leakage** in the enhanced NSL-KDD
archive. The Digital-Twin (DT) feature block in `data/real_datasets/nsl_kdd_with_dt_processed.csv`
was generated with access to the ground-truth label, so a classifier trained on
those features recovers the label almost perfectly without learning anything about
intrusion detection. Release `v1.0` is therefore **withdrawn** and replaced by
`v1.1`, in which the synchronization features are regenerated **blind to the label**.

This notice is published so that anyone who downloaded `v1.0` can discard it, and
so that the audit is on the record rather than silently overwritten.

## What was wrong

Measured on the published file (125,973 rows), target `is_attack`:

| Column | Finding |
|---|---|
| `is_malicious` | Pearson *r* = **+1.000** with the target — an exact duplicate of the label |
| `severity_level` | Non-null **only** for attack rows (67,343 nulls, all of them normal traffic) |
| `anomaly_detection_score` | *r* = **+0.939** |
| `twin_health_score` | *r* = **−0.861** |
| `sync_accuracy_score` | *r* = **−0.710** |
| `classification_entropy` | *r* = **+0.640** |
| `prediction_confidence` | *r* = **−0.587** |

Dropping only the two exact duplicates is **not** a fix. RandomForest (100 trees,
stratified 80/20 split):

| Input | Accuracy |
|---|---|
| DT features + `is_malicious` (as published in v1.0) | **100.00 %** |
| DT features after dropping `is_malicious` and `severity_level` | **99.98 %** |
| `anomaly_detection_score` alone | **98.94 %** |

The entire DT feature block is a function of the label, so the leakage cannot be
removed column by column — the features have to be regenerated. (`confidence_label`,
despite its name, is a continuous value uncorrelated with the target, *r* = +0.001,
and is not a leak.)

Two further discrepancies between `v1.0` and the dataset description are corrected
in `v1.1`: the archive contained **50,000** synthetic samples, not 125,000, and it
shipped `KDDTrain+` only, with no `KDDTest+`, so no held-out evaluation on the
standard NSL-KDD split was possible from the release alone.

## What v1.1 contains

Synchronization features regenerated by `data/build_clean_dataset.py`, which never
reads the `label` column, together with the standard NSL-KDD split:

- `nslkdd_train_cleansync.csv` — 125,973 rows (`KDDTrain+`)
- `nslkdd_test_cleansync.csv` — 22,544 rows (`KDDTest+`)
- 8 synchronization features, plus an 8-column randomized control block (`rnd_*`)
  generated identically from shuffled inputs, so a reported gain can be compared
  against a no-signal baseline.

Verification of the replacement, RandomForest trained on `KDDTrain+` and evaluated
on `KDDTest+`:

| Input | Accuracy | AUC |
|---|---|---|
| Synchronization features alone | 71.53 % | 0.8273 |
| Randomized control alone | 47.59 % | **0.5042** |

No column in `v1.1` has \|*r*\| > 0.8 with the target, and the control block sits at
chance, which is what a leak-free feature set should look like.

## Effect on the reported results

The accuracy figures reported in earlier revisions of this README and in the
manuscript were produced on the leaking data and do not hold on the corrected set.
Under the clean protocol the synchronization features still carry genuine signal —
they raise RandomForest accuracy and F1 over the network features alone, while the
randomized control does not — so the effect is real but considerably smaller than
published. Revised figures accompany the current version of the manuscript.
